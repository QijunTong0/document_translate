# document_translate

英語論文の LaTeX ソース（arXiv などで配布される zip / tar.gz）を日本語に翻訳し，日本語の PDF を作成するスクリプトです．

- 翻訳には，ユーザーが契約している **Claude Code**（`claude -p`）または **Codex**（`codex exec`）の非対話モードを使います．
- 日本語の組版は **Docker 上の TeX Live（LuaLaTeX + LuaTeX-ja）** で行うため，手元に日本語 TeX 環境を用意する必要はありません．
- 元の tex ファイルの本文を訳して置き換えるので，レイアウト，数式，参照，参考文献は元の論文のまま保たれます．
- 図はそのまま使います．画像ファイルや TikZ で描かれた図の中の英語は訳しません（キャプションは訳します）．

## 必要なもの

- Python 3.9 以降（標準ライブラリのみを使用）
- Docker
- 次のどちらか（ログイン済みであること）
  - Claude Code の `claude` コマンド
  - Codex CLI の `codex` コマンド

## 使い方

```sh
# Claude Code で翻訳する（既定）
./translate_paper.py paper.zip -o out/

# Codex で翻訳し，モデルを指定する
./translate_paper.py paper.tar.gz -o out/ --engine codex --model <モデル名>
```

`out/` には次のものが出力されます．

| パス | 内容 |
| --- | --- |
| `<入力名>_ja.pdf` | 日本語の PDF |
| `<入力名>_ja_src.zip` | 翻訳済みの LaTeX ソース |
| `<入力名>_ja_work/` | 作業ディレクトリ（下記） |

初回は Docker イメージ（TeX Live 一式，数 GB）の取得と作成に時間がかかります．

### 作業ディレクトリと再実行

作業ディレクトリには次のものが置かれます．

| パス | 内容 |
| --- | --- |
| `glossary.tsv` | 自動生成した用語集 |
| `cache/` | 断片ごとの翻訳結果 |
| `logs/` | エンジンに渡したプロンプトと応答 |
| `report.json` | 断片ごとの結果 |
| `ja/` | 翻訳済みソースとコンパイル結果 |

同じコマンドを再実行すると，翻訳済みの断片はキャッシュから再利用され，翻訳に失敗した断片だけが翻訳し直されます．

- 訳語を直したい場合は `glossary.tsv` を編集して再実行してください．用語集が変わると全体を翻訳し直します．
- 翻訳済みソース（`ja/` 以下）を手で直した場合は，`--build-only` でコンパイルだけをやり直せます．

### 主なオプション

| オプション | 内容 |
| --- | --- |
| `--engine {claude,codex,command}` | 翻訳エンジン．`command` は `--engine-cmd` で指定した任意のコマンド（標準入力でプロンプトを受け取り，標準出力に応答を書くもの） |
| `--model`, `--engine-arg` | エンジンに渡すモデル名と追加の引数 |
| `-j, --jobs` | 同時に実行する翻訳の数（既定: 3） |
| `--prompt FILE` | 翻訳の指示（`prompts/translate_ja.md`）を置き換える |
| `--prompt-append FILE`, `--instruction TEXT` | 翻訳の指示に追記する（複数指定可） |
| `--punctuation {comma-period,touten-kuten}` | 句読点を「，．」にするか「、。」にするか（既定: `comma-period`） |
| `--glossary FILE` | 訳語を指定する用語集．自動生成の用語集より優先する |
| `--no-auto-glossary`, `--regenerate-glossary` | 用語集を自動生成しない／作り直す |
| `--main`, `--include`, `--exclude` | 主ファイルの指定，翻訳対象に含める／除く tex ファイル |
| `--chunk-chars` | 1 回の翻訳で渡す最大文字数の目安（既定: 8000） |
| `--keep-english-names` | Figure，Table などの見出し語を日本語化しない |
| `--no-build`, `--build-only` | PDF を作らない／翻訳せずにコンパイルだけ行う |
| `--no-docker` | Docker を使わず手元の `latexmk` でコンパイルする |
| `--shell-escape` | `-shell-escape` を付けてコンパイルする（minted など） |
| `--dry-run` | 翻訳対象のファイルと分割結果を表示するだけで終了する |

すべてのオプションは `./translate_paper.py --help` で確認できます．

用語集は 1 行に 1 語，`英語<TAB>訳語<TAB>備考` の形式で書きます．訳さない語は訳語の列に原語をそのまま書きます．

```
kernel	カーネル	正定値カーネルの意味
attention	attention	訳さない
```

## 処理の流れ

1. **展開と解析**
   - アーカイブを展開し，`\documentclass` と `\begin{document}` を含む主ファイルを特定します．
   - `\input` や `\include` などを辿って，読み込まれる tex ファイルを文書中の順に集めます．
   - マクロ定義だけのファイルや，TikZ などの図だけのファイルは翻訳対象から外します．
2. **前処理と分割**
   - コメントだけの行を削除します．
   - verbatim，lstlisting，tikzpicture，thebibliography などの環境と `\verb` を `[[[KEEP_0001]]]` のような目印に置き換え，翻訳されないよう保護します．
   - 段落の区切りで断片に分割します．
   - プリアンブルは，`\title` などの組版される文章を含む部分だけを翻訳に回します．
3. **用語集の作成**：論文全体を一度エンジンに渡し，訳語を統一するための用語集を作ります．
4. **翻訳**：断片ごとに次のものをまとめてエンジンに渡し，並列に翻訳します．
   - 翻訳の指示
   - 用語集
   - 論文の概要（タイトル，アブストラクト，章立て）
   - 直前の原文
   - 翻訳する断片
5. **検査**：訳文について次の点を検査します．
   - 構造：`\begin`／`\end`，波括弧，`$`，`\label`，保護領域の目印が原文と一致するか．
   - 未翻訳：日本語に訳されているか．
   - 欠落：訳文が原文に比べて極端に短くないか．

   問題があれば，その内容を伝えて再翻訳させます．再試行しても直らない断片は，コンパイルを壊さないよう原文のまま残し，その旨を表示します．
6. **組版**
   - 主ファイルに `\usepackage{luatexja}` を加えます．
   - 図・表・参考文献などの見出し語（`\figurename` や cleveref の名前など）を日本語にします．
   - Docker 上で `latexmk -lualatex` によりコンパイルします．コンテナはネットワークを切断して実行します．

## 翻訳の指示（プロンプト）について

既定の指示は [`prompts/translate_ja.md`](prompts/translate_ja.md)，用語集を作るための指示は [`prompts/glossary_ja.md`](prompts/glossary_ja.md) にあります．AI による論文翻訳で起こりやすい問題に対して，次の点を指示しています．

- **専門用語を無理に訳さない**
  - 訳語を選ぶ基準を「その分野の日本語の論文・教科書で実際に使われている表記」に置きます．
  - 判断の順序を「用語集 → 定訳 → 慣用のカタカナ → 英語のまま」と明示します．
  - 辞書的な直訳による造語を禁じ，迷った場合は英語のまま残すよう指示します．
  - 固有名詞，略語，論文独自の命名は原文表記のまま残します．
- **訳語の一貫性**
  - 断片ごとに翻訳すると，同じ語の訳が揺れやすくなります．
  - そこで，翻訳の前に論文全体から用語集を作り，すべての断片に同じ用語集を渡します．
  - 多義語（kernel，attention，state など）については，分野と文脈から訳語を決めるよう明示します．
- **文脈を無視しない**
  - 各断片には，論文の概要（タイトル，アブストラクト，章立て）と直前の原文を参考情報として渡します．
  - 指示語や代名詞は，日本語で曖昧になる場合に限り，指す名詞を補うよう指示します．
- **内容の正確さ**
  - 省略・要約・加筆を禁じます．
  - ヘッジ表現（may，suggest など）による確信度，否定・数量の限定，respectively の対応関係，論理接続を保つよう指示します．
  - 原文が曖昧な箇所は推測で確定させないよう指示します．
- **論文の文体**
  - 常体（である調）に統一し，句読点の種類を指定します．
  - 翻訳調を避けるため，次のような具体例を示します．
    - 主語の「我々は」の多用（→「本稿では」）
    - 無生物主語の直訳
    - 機械的な受動態
    - 「〜することができる」
  - 見出しの訳し方，「図\ref{}」「\ref{} 節」などの参照の書き方，英数字の半角化を指定します．
  - 日本語と英数字の間に空白を入れないよう指定します．間隔は LuaTeX-ja が自動で調整します．
- **LaTeX として壊さない**
  - 翻訳する部分（本文，見出し，キャプション，脚注など）と，変更してはいけない部分を列挙します．
  - 変更してはいけない部分は，コマンド，キー，数式，コメント，コード，図の描画コード，マクロ定義，参考文献です．

分野特有の慣習や訳語の好みは `--instruction` や `--prompt-append` で追記できます．指示全体を置き換えたい場合は `--prompt` を使います．出力形式の指定はスクリプトが毎回付け加えるため，指示を置き換えても結果の取り出しには影響しません．

## 制限

- 組版には LuaLaTeX を使います．pdfLaTeX 専用のパッケージや命令に依存するソースは，コンパイルに失敗することがあります．その場合は `ja/` 以下のソースを修正し，`--build-only` で再コンパイルしてください．
- 画像として埋め込まれた図の文字は翻訳しません．
- 翻訳の品質と所要時間は，使うエンジンとモデルに依存します．

## テスト

```sh
python3 -m unittest discover -s tests
```

テストでは，実際の翻訳エンジンの代わりに `tests/fake_engine.py`（文章の行頭に印を付けるだけのダミー）を使います．翻訳エンジン以外の処理は，次のように手元で一通り確認できます．

```sh
(cd tests/fixtures/sample_paper && zip -qr /tmp/sample.zip .)
./translate_paper.py /tmp/sample.zip -o /tmp/out --engine command --engine-cmd "python3 tests/fake_engine.py"
```
